# Task 01: Product Filter Panel

## Цель
Сделать первый практический UI-блок с реальной фронтенд-логикой:
1. Фильтрация карточек по категории.
2. Поиск по названию.
3. Сортировка.
4. Корректный рендер пустого состояния.

Это не «учебный вакуумный пример», а базовый паттерн из реальных интерфейсов.

## Что ты должен собрать

1. Экран с темным фоном и светлой рабочей областью (листом).
2. Внутри листа блок фильтрации:
- Заголовок секции.
- Чипы категорий.
- Поле поиска.
- `select` сортировки.
- Кнопка сброса.
- Строка счетчика результатов.
- Сетка карточек.
- Пустой стейт, если результатов нет.
3. Вся сетка карточек рендерится из массива данных в `js/script.js`.

## Визуальное ТЗ (без макета, но с четкими правилами)

### Общий стиль

- Фон страницы: темный графитовый.
- Рабочая область: светлая, со скруглением и тонкой рамкой.
- Акцентный цвет интерактивов: красный.

### Контролы

- Чипы категорий: `All`, `UI`, `JS`, `Tools`.
- Высота чипов около `30px`.
- Активный чип визуально отличается (заливка + цвет текста).
- Поле поиска на всю ширину строки.
- Рядом или ниже строка с `select` и кнопкой `Reset`.

### Блок карточек

- На мобильном: 2 карточки в ряд.
- На ширине от `900px`: 3 карточки в ряд.
- Карточка белая, скругленная, с рамкой.
- Вверху карточки цветной прямоугольник-плейсхолдер вместо изображения.
- Ниже: название, категория, цена.

### Пустое состояние

- Отдельный блок с текстом `No products found`.
- Подсказка `Try changing filters or search query`.

## Поведение (обязательно)

### Категории

- `All` показывает все карточки.
- Остальные фильтруют по `item.category`.
- В один момент активна только одна категория.

### Поиск

- Ищет по `title`.
- Поиск нечувствителен к регистру.
- Перед сравнением строка обрезается через `trim()`.

### Сортировка

- `price asc`
- `price desc`
- `name a-z`

### Reset

- Сбрасывает категорию в `All`.
- Очищает поиск.
- Возвращает сортировку по умолчанию.
- Возвращает полный список.

### Счетчик

- Всегда показывает актуальное количество после каждого изменения.

## Технические ограничения

1. Только чистый JavaScript (без библиотек).
2. Один источник данных: массив объектов.
3. Карточки не хардкодить в HTML.
4. Обновление UI делать через общий рендер, а не разрозненные правки DOM в разных местах.

## Минимальная структура данных

```js
{
  id: 1,
  title: "UI Kit Alpha",
  category: "UI",
  price: 39,
  imageColor: "#DCEBFF"
}
```

## Рекомендуемая архитектура (ориентир)

1. `getControlsState()` — прочитать активные фильтры.
2. `filterItems(items, state)` — вернуть отфильтрованный массив.
3. `sortItems(items, state)` — вернуть отсортированный массив.
4. `renderCards(items)` — отрисовать карточки.
5. `renderEmptyState(isEmpty)` — показать/скрыть пустой стейт.
6. `renderResultsCount(count)` — обновить счетчик.
7. `render()` — единая точка обновления интерфейса.

## Критерии готовности

1. Категория + поиск + сортировка работают одновременно.
2. Reset полностью возвращает исходный вид.
3. Пустой стейт корректно появляется и скрывается.
4. Никаких ошибок в консоли.
5. Код читаемый и разбит на функции, без копипасты логики.
