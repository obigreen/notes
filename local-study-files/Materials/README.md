# Materials New

Это очищенная рабочая база по материалам из исходной папки `Materials`. Она создана не как ещё один архив, а как навигационный слой для совместной работы ученика и AI-ментора.

Исходные 1 662 файла и существовавшие подпапки `Materials` не изменены и не удалены; добавлена только папка `Materials New`. Если в этой базе чего-то нет, это не означает удаление: решение и путь к источнику должны быть зафиксированы в разделе [`00-meta`](00-meta/source-audit.md).

## Контекст ученика

- Сильная сторона: богатый практический опыт в HTML, CSS, адаптивной вёрстке и работе по Figma.
- Главный пробел: JavaScript ещё не стал языком, на котором код пишется уверенно и самостоятельно.
- Текущая цель: JavaScript → TypeScript → React и связанный фронтенд-стек.
- Следующий горизонт: Next.js после уверенной базы React.
- Backend нужен позже — как расширение до fullstack с упором на frontend, а не как параллельный учебный трек сейчас.
- Главный риск: подменить практику накоплением курсов, ссылок, технологий и чужих решений.
- Двойная боль: страшно потерять полезное и одновременно страшно снова застрять в огромном архиве. Поэтому оригиналы и подробный ledger сохраняют память, а активный маршрут остаётся коротким.

## Роли четырёх слоёв

1. **Приложение-конспект в `src/recordsdirectory`** — быстрый словарь синтаксиса, методов и коротких примеров.
2. **`Materials New`** — объяснения связей, пробелы приложения, рыночные приоритеты, практика и проектный контекст.
3. **Исходное содержимое `Materials` вне `Materials New`** — неизменяемый архив и доказательная база.
4. **`local-study-files/obsidian-interview-questions-and-information` и `local-study-files/Roadmap_frontend_new`** — отдельные базы, намеренно не открывавшиеся и не смешивавшиеся с этой итерацией.

## Приоритеты

- **P0 — сейчас:** без этого нельзя уверенно писать и объяснять React-код.
- **P1 — следующим слоем:** нужно для рабочего frontend-проекта и собеседований.
- **P2 — после базы:** полезно, но не должно задерживать выход на рынок.
- **Later:** осознанно отложено; это не текущий учебный долг.
- **Archive:** источник сохранён, но превращать его в задачу не нужно.

## Правила для AI-ментора

1. Перед учебной сессией учитывать профиль и приоритеты из этого файла.
2. Для синтаксиса сначала проверять приложение; не дублировать уже хорошо раскрытую карточку длинной теорией.
3. Для темы использовать один основной конспект из этой базы, а не выдавать новый список из десятков ресурсов.
4. Давать цикл: короткое объяснение → вопрос на воспроизведение → код руками → отладка → объяснение решения.
5. Не считать тему освоенной только потому, что пример понятен при чтении.
6. Если материал спорный или устаревающий, сверять его с первичной документацией.
7. Не поднимать backend, DevOps, микросервисы, Kubernetes, сложный Next.js или архитектурные моды, пока они не нужны текущему фронтенд-заданию.
8. При добавлении новой информации обновлять не только тематический файл, но и журнал источников/решений.

## Критерий «тема освоена»

Тема считается рабочей, когда ученик может:

1. объяснить её своими словами без подсказки;
2. написать минимальный пример с нуля;
3. найти и исправить типичный баг;
4. применить её в маленькой задаче;
5. ответить, когда решение не подходит и какой у него компромисс.

## Правило против нового информационного склада

Новый ресурс не становится частью активного плана автоматически. Сначала определяется:

- какой конкретный пробел он закрывает;
- нет ли этого уже в приложении или здесь;
- нужна ли информация до ближайшего проекта/собеседования;
- будет ли после чтения практическое действие.

Если ответа нет, ресурс остаётся в архиве, а не превращается в обязательство.
